# 订单数据口径规范（单一事实来源）

更新：2026-08-24。任何涉及订单/退款统计的改动必须与本文件保持一致；
改口径前先改本文件，再改代码与测试。

## 1. 统一字段语义

| 字段 | 含义 |
|---|---|
| totalOrderCount | 总订单（成交口径，含退款单，不含纯取消/待付款） |
| validOrderCount | 有效订单 / 去退款单数（= 总订单 − 退款订单） |
| refundedOrderCount | 退款订单（按订单去重，不按售后记录条数） |

恒等式：**totalOrderCount = validOrderCount + refundedOrderCount**。
任何页面、报表、天梯都必须满足；诊断脚本会检查数据库层的不变量。

## 2. 退款归属规则（关键）

- 退款**按订单归属日归集**：一笔退款永远算在“订单创建当天”，
  不按退款发生日（update_time/create_time）归集。
- 跨日退款（昨天下单今天退款）→ 归到昨天。
- 退款订单判定：售后状态为成功退款（抖店 12/27；微信 `MERCHANT_REFUND_SUCCESS` 且金额 > 0）。
- 退款金额同样归到订单日。

## 4. 状态码映射（抖店）

- 2 待发货 / 3 已发货 / 4 已关闭 / 5 已完成 / 21 已关闭。
- 营收订单 = 非关闭 + 关闭但有成功退款。
- 有效订单 = 营收订单 − 成功退款订单。

## 5. 防回归要求

1. 单测必须覆盖“跨日退款归订单日”场景（后端 `doudian-store-metrics.spec.ts`、
   前端 `doudianStoreMetrics.test.ts` 已有该用例，禁止删改回旧语义）。
2. `scripts/diagnose-production.py --remote` 新增数据库不变量检查：
   重复订单/售后行、无主退款孤儿行必须为 0。
3. 每日自动对账（`daily-reconciliation.scheduler.ts`，北京时间 09:10，手动触发
   `POST /api/v1/scheduler/trigger/reconciliation`）：每家抖店昨日数据用两条独立
   路径重算（页面口径 vs 纯 SQL 重算），六个字段任一处不一致即推 🔴 飞书异常；
   一致则推 ✅ 明细供人工与抖店后台核对。另按“店铺订单最早同步时间”拆分孤儿
   退款：同步开始后发起的算 ⚠️ 疑似缺口（需核对），之前的算 ℹ️ 历史口径外
   （订单从未采集，正常不计入统计）。
4. 部署后核对样例：用 `GET /api/v1/doudian-browser/shop/summary` 验证
   total = valid + refunded。
